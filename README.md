# Somarawad.github.io

Portfolio of **Somar Awad**, creative technologist in Montreal: AI video for advertising, and the custom ComfyUI tools that keep it on brand.

Live at **https://somarawad.github.io/** once GitHub Pages is turned on (see the end of this file).

It's a plain static site: HTML, one CSS file, one small JavaScript file. No framework, no build step on GitHub's side, no tracking, no cookies. All the content lives in one file, `data/projects.json`; a small Python script turns it into the HTML pages, and those generated pages are committed so GitHub Pages serves them as they are.

## Pages

| Page | File |
|---|---|
| Home: showreel, positioning, project grid, toolkit, contact | `index.html` |
| One case study per project | `work/<slug>/index.html` |
| About: bio, background, tools, languages | `about/index.html` |
| Not found | `404.html` |

## Folder layout

```
data/projects.json     all the words, projects, media slots and pipeline diagrams
templates/             page layouts (base, home, project, about, 404)
assets/css/site.css    all the styling (colours and fonts are at the top)
assets/js/site.js      theme toggle, before/after slider, video embeds, reveals
assets/fonts/          Instrument Serif (self-hosted, SIL Open Font License)
assets/og/             social share images, one per page (made by tools/make_assets.py)
media/                 your images and videos (see ADD_MEDIA.md)
tools/build.py         generates the HTML from data + templates (Python 3 standard library)
tools/check.py         validates data, links and assets; lists missing media
tools/make_assets.py   regenerates share images and favicons (needs Pillow)
tools/screenshots.mjs  optional phone + desktop screenshots (needs Node + Playwright)
docs/screenshots/      screenshots of every page
```

**Never edit `index.html`, `about/`, `work/` or `404.html` by hand**: they are overwritten on every build. Edit `data/projects.json` or `templates/` and rebuild.

## Edit, rebuild, preview

You need Python 3.9 or newer (`python3 --version`). Nothing to install.

```bash
python3 tools/build.py
```

```bash
python3 tools/check.py
```

```bash
python3 -m http.server 8000
```

Then open http://localhost:8000. Stop the server with Ctrl+C. On Windows, use `py` instead of `python3`.

When it looks right, commit and push; GitHub Pages updates in a minute or two.

```bash
git add -A && git commit -m "Update portfolio" && git push
```

## Editing content

Everything is in `data/projects.json`. JSON is strict: keep the double quotes, and no comma after the last item in a list. `tools/check.py` tells you exactly where a mistake is.

Text fields allow three bits of markup: `*italic*` (shown in the serif, in the accent colour in headlines), `**bold**`, and `[link text](https://example.com)`.

### Site-wide (`"site"`)

`headline` and `supporting` are the first thing a recruiter reads. `flow` is the five-step strip under the showreel. `open_to` is the line on the About page. `about` holds the bio, background timeline and tool groups. Contact links are `email`, `linkedin`, `github`.

### A project

```json
{
  "slug": "to-nora",                 // the URL: /work/to-nora/  (lowercase, hyphens)
  "title": "To Nora",
  "card_title": "Optional shorter title for the home grid",
  "category": "Short film",          // small label above the title
  "year": "2025",                    // leave "" to hide
  "dates": "Optional, e.g. Jun 2025 – present (shown instead of year on the page)",
  "role": "Writer, director, AI generation",
  "published": true,                 // false hides it everywhere (page, grid, sitemap)
  "featured": true,                  // true makes the card big on the home grid
  "wip": false,                      // true adds a "Work in progress" badge and note
  "order": 2,                        // position on the home page, lowest first
  "palette": ["#0c1412", "#3d5a4a"], // the two colours of its placeholder frames
  "tagline": "One line under the title",
  "summary": "Two lines on the home page card",
  "brief": "The one-paragraph brief on the case study",
  "what_i_did": ["Bullet", "Bullet"],
  "tools": ["Chip", "Chip"],
  "note": "Optional boxed note, e.g. a disclaimer",
  "note_prominent": false,           // true gives the note an accent border
  "media": [ ... ],                  // media slots, see below
  "sections": [ ... ],               // the process part of the page, see below
  "results": [{"value": "$600", "label": "total budget"}],
  "credits": [{"role": "Written and generated by", "name": "Somar Awad"}],
  "links": [{"label": "Code on GitHub", "url": "https://github.com/..."}]
}
```

(The `//` comments are only for this README; don't put comments in the real file.)

**To hide NOVARA** (or any project) until it's ready: set `"published": false` and rebuild. Its page is removed and it disappears from the grid, the "next project" links and the sitemap. Set it back to `true` to bring it back. To keep it visible but drop the "Work in progress" label, set `"wip": false`.

### Media slots

Each slot has an `id` (the one called `hero` is the big frame at the top of the case study and the thumbnail on the home page), a `type`, a `label` (printed on the placeholder), `alt` text, an optional `caption`, and the exact file path(s) it expects:

| type | fields | shows as |
|---|---|---|
| `video` | `src` (mp4), `poster` (jpg), optional `embed` (YouTube/Vimeo URL) | muted loop that plays when on screen |
| `image` | `src` | still image |
| `compare` | `before`, `after`, `alt_before`, `alt_after` | before/after slider (drag, or arrow keys) |
| `embed` | `url` (YouTube/Vimeo), `poster`, fallback `src` (mp4) | thumbnail with a play button; the player loads only on click. YouTube uses the privacy-enhanced `youtube-nocookie.com` domain |

If a file is missing, a placeholder is shown. If it exists, it's used. See **ADD_MEDIA.md** for the full list of expected files, sizes and ffmpeg commands.

### Sections (the process part of a case study)

A list of blocks, shown in order between "What I did" and "Results":

| type | fields |
|---|---|
| `text` | `heading`, `body` (a string or a list of paragraphs) |
| `list` | `heading`, `items` |
| `steps` | `heading`, `intro`, `items: [{title, body}]`, numbered cards |
| `pipeline` | `heading`, `intro`, `pipeline`: the name of a diagram under `"pipelines"` |
| `compare` | `heading`, `intro`, `media`: list of compare slot ids |
| `gallery` | `heading`, `media`: list of slot ids (1, 2, 3 or 4 work best) |
| `film` | `heading`, `media`: one slot id, played with sound and controls |
| `stats` | `heading`, `stats: [{value, label}]`, optional `media` screenshot slot id |

### Pipeline diagrams

Defined under `"pipelines"` at the bottom of the file and drawn as inline SVG, laid out in four columns on desktop, two on tablets and one on phones. Each node has a `label`, a `detail` sentence, optional `tags` (options or routes, shown as pills), `"custom": true` to highlight it as your own node, and `"kind": "io"` for the dashed input/output boxes. Change the words and rebuild; the layout adjusts itself.

## Adding a project

1. Copy an existing project block in `data/projects.json` (from `{` to the matching `},`), paste it where you want it, and change `slug`, `title`, `order` and the text.
2. Change every media path to the new folder, e.g. `media/new-project/hero.mp4`.
3. Run `python3 tools/build.py`, then `python3 tools/check.py`.
4. Optional: `pip install pillow` then `python3 tools/make_assets.py` to make its share image (`assets/og/<slug>.jpg`). Until then it uses the default share image.
5. Preview, then commit and push.

## Changing the look

Colours, fonts and spacing are CSS variables at the top of `assets/css/site.css` (dark theme in `:root`, light theme in `:root[data-theme="light"]`). There is one accent colour, `--accent`. After editing the CSS or JS, bump `ASSET_VERSION` at the top of `tools/build.py` and rebuild, so returning visitors don't get the old cached file.

The theme follows the visitor's system setting; the toggle in the header overrides it and remembers the choice in the browser's local storage (not a cookie, never sent anywhere).

## Checks and screenshots

`python3 tools/check.py` validates `projects.json` (fields, types, unique slugs, media paths, section references), checks every internal link, image, script, stylesheet and `#anchor` in the generated pages, reports present and missing media, and checks the home page stays under 150 KB without media (it's about 95 KB, most of it the two font files). It exits with an error code if something is broken; missing media is only reported.

Screenshots of every page at phone (390×844) and desktop (1440×900) sizes are in `docs/screenshots/`. To regenerate them (needs Node and Playwright):

```bash
npm install --no-save playwright && npx playwright install chromium
```

```bash
python3 -m http.server 8000
```

```bash
node tools/screenshots.mjs http://localhost:8000
```

Add `THEMES=dark,light` in front of the last command to capture both themes.

## Turning on GitHub Pages

1. Merge this branch into `main`.
2. On GitHub: **Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: `main`, folder `/ (root)` → Save.**
3. Wait a minute or two, then open https://somarawad.github.io/.

GitHub Pages on a free account only works for **public** repositories. When the site is ready to be seen: **Settings → General → Danger Zone → Change repository visibility → Make public.** Everything in the repo becomes visible, including `data/projects.json` and anything in `media/`, so only commit what you're happy to show.

The empty `.nojekyll` file tells GitHub to serve the files as they are, without running Jekyll.

## Privacy

No analytics, no cookies, no third-party scripts. Fonts are self-hosted. The only outside requests happen if you add a YouTube or Vimeo link: the YouTube thumbnail image loads with the page, and the player itself loads only when the visitor presses play.
